# AI에 붙여 넣는 프롬프트

`<...>`는 사람이 채우는 부분이다. 미정인 내용을 AI가 이미 확정된 것으로 추정하지 않게 한다.

## 모든 도구의 첫 대화 · 팀원 둘에게도 동일하게 전달

```text
저장소 루트의 AGENTS.md와 docs/BRIEF.md를 읽어줘.
현재 브랜치·변경 상태를 확인하고, 읽은 규칙 파일 경로와 공통 규칙 3개를 요약해줘.
공식 확인 사항 / 아직 미정인 사항 / 내 담당 경로를 구분해줘.
지금은 환경과 준비 상태 확인 단계야. 앱 스택이나 제품 기능을 임의로 확정하지 마.
준비 스크립트를 실행할 수 있으면 doctor와 check-prep의 실제 결과를 보고해줘.
```

## 주제 공개 직후 · 기획 담당

```text
공식 주제: <원문>
규정과 평가 기준: <공식 링크와 확인한 내용>
남은 개발 시간: <시간>, 발표 시간: <시간>
세 명이 익숙한 기술: <기술>, 사용 가능한 서비스: <서비스>
AGENTS.md를 읽고, 핵심 흐름 하나로 시연할 수 있는 후보를 최대 3개 비교해줘.
주제 적합성·구현 시간·외부 서비스 의존·데모 관점으로 비교하고 하나를 추천해줘.
필수 기능은 최대 3개, 제외 범위와 완료 조건을 포함해 docs/BRIEF.md 초안을 작성해줘.
공식 규정과 추천을 구분해줘. 아직 앱 구현은 시작하지 마.
```

## 기능 구현 · 사람마다 한 작업씩

```text
AGENTS.md와 docs/BRIEF.md를 읽고 아래 작업을 구현해줘.
담당자 / 작업 ID: <B / T2>
목표: <사용자 관점의 동작>
수정 가능한 경로: <명확한 파일 또는 폴더>
입출력 계약: <합의된 계약 파일과 샘플>
완료 조건: <정상·빈 결과·오류 상태와 확인 방법>
남은 시간: <시간>
다른 사람의 변경을 보존하고 담당 경로 안에서 구현해줘.
공통 설정·계약·의존성 변경이 필요하면 영향과 요청안을 알려줘.
변경에 맞는 검사를 실행한 뒤 변경 파일·명령·결과·NOT RUN·남은 문제를 보고해줘.
```

## 다른 도구로 검토 · 읽기 전용

```text
AGENTS.md와 docs/BRIEF.md를 읽어줘. 파일은 수정하지 마.
검토 대상: <브랜치 / 커밋 / PR / diff>
완료 조건: <관찰 가능한 동작>
실행 오류·입출력 계약 불일치·비밀값 노출·오류/빈 결과 상태·데모 실패 가능성을 검토해줘.
실제 근거가 있는 문제만 심각도·파일 위치·재현 방법과 함께 보고해줘.
직접 확인한 사실과 추정을 구분하고, 검사를 안 했다면 NOT RUN이라고 적어줘.
```

## 도구·사람 전환 시 인수인계

```text
작업 ID / 담당자:
현재 checkout 경로 / 브랜치 / 마지막 커밋:
목표 / 수정 가능 경로 / 완료 조건:
지금까지 변경한 파일 / 미커밋 변경:
입출력 계약 / 소비자:
실행한 검사와 결과:
NOT RUN:
재현되는 문제 / 다음 한 단계:
PR / 실행 또는 배포 URL:

이 상태와 실제 파일을 확인한 뒤 이어서 진행해줘.
다른 사람의 변경은 보존하고, 이미 끝낸 작업을 다시 만들지 마.
```

## 마감 전 점검

```text
AGENTS.md, docs/BRIEF.md, docs/DEMO.md를 읽어줘.
새 기능은 추가하지 말고 필수 흐름과 제출물을 확인해줘.
실제 실행한 빌드·핵심 동작·배포 URL 검사만 결과에 포함해줘.
제출 차단 문제 / 시연 영향 문제 / 이후 개선으로 분류해줘.
규정·사용자 동작·샘플 표시·제출 URL·실행 안내 누락을 확인하고 미검증은 NOT RUN으로 적어줘.
```
