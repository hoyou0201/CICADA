# 주제 공개 후 팀 합의서

`미정`과 빈 체크박스는 미확인이다. 예시를 공식 규정이나 합의로 해석하지 않는다.

## 대회 사실

| 항목 | 확인 내용 | 공식 근거 |
| --- | --- | --- |
| 대회명·링크·주제 원문 | 미정 | 미정 |
| 개발 시작/끝·시간대·발표 시간 | 미정 | 미정 |
| 제출물·제출처·마감 | 미정 | 미정 |
| 평가 항목·배점 | 미정 | 미정 |
| 사전 코드·템플릿·기존 프로젝트 허용 | 미확인 | 미정 |
| AI 도구·외부 API·데이터·소재 허용 | 미확인 | 미정 |
| 개발 기록·출처·라이선스 표기 요구 | 미확인 | 미정 |

## 제품을 한 문장으로

- 대상 사용자: 미정
- 그 사용자가 지금 겪는 구체적 문제: 미정
- 핵심 동작과 결과: 미정
- 주제·평가 기준과 연결되는 이유: 미정
- 1분 데모에서 관객이 확인할 가치: 미정

후보는 각자 1개씩 제시한다. 주제 적합성·문제의 명확성·시간 내 구현·시연 가능성을 비교한다.
규정에 맞고 가장 작은 핵심 흐름으로 가치를 보여 주는 후보를 선택한다.

## 범위와 일정

- 기능 목록(우선순위 순, 개수 제한 없음) / 기능마다 관찰 가능한 완료 조건: 미정
- 이번에 제외할 기능: 미정
- 첫 통합 시각 / 첫 배포 시각 / 새 기능 중단 시각: 미정

기능 개수는 정하지 않는다. 우선순위 순으로 나열하고 시간 안에 끝낼 수 있는 만큼만 한다. 기능마다 정상 동작·빈 결과·오류 상태를 합의한다.
새 제안은 필수 흐름 완성 뒤 검토한다. 추가하면 기존 범위에서 뺄 것을 함께 정한다.

## 기술과 실행 계약

| 결정 | 합의 |
| --- | --- |
| 플랫폼·언어·프레임워크·런타임 버전 | 미정 |
| 패키지 도구·버전·lockfile | 미정 |
| 의존성 설치 / 로컬 실행 / 포트 | 미정 |
| lint / 타입 검사 / 테스트 / 빌드 명령 | 미정 |
| 배포 서비스·명령·담당·URL | 미정 |
| 데이터 저장·외부 API·비밀값 저장 위치 | 미정 |
| 환경 변수 이름·필수 여부·공유 방법 | 미정 |

결정 후 `.env.example`과 앱용 CI를 추가한다. 준비용 CI 성공과 앱 빌드 성공을 구별한다.
실제 키는 안전한 별도 경로로 전달하고, 비밀값이나 `.env` 내용을 AI에 출력하지 않는다.

## 담당과 작업표

| ID | 사람 | 목표 | 수정할 경로 | 의존 작업 | 완료 조건 | 브랜치/PR | 상태 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| T1 | A | 공통 골격·첫 통합 | 미정 | 없음 | 시작→핵심 동작→결과 흐름 실행 | 미정 | 미착수 |
| T2 | B | 기능 1 전체 흐름 | 미정 | T1의 계약 | 미정 | 미정 | 미착수 |
| T3 | C | 기능 2 전체 흐름 | 미정 | T1의 계약 | 미정 | 미정 | 미착수 |

문서 작업표·공통 타입·라우트·전역 스타일·의존성·배포 설정의 통합 담당: A (변경 가능).
하나의 파일을 둘이 소유하지 않는다. PR을 반영하기 전에 소비 코드와 합의된 계약이 맞는지 확인한다.

## 데이터·화면 계약 · 구현 전 합의

- 생산자 / 소비자 / 계약 파일 경로: 미정
- 입력 필드·타입·필수 여부·유효성 조건: 미정
- 성공 결과·빈 결과의 형태와 예시: 미정
- 실패 코드·사용자 메시지·타임아웃·재시도: 미정
- 샘플 데이터 경로 / 실제 API 전환 방법 / 샘플 표시: 미정
- 계약 변경 담당·변경 통보 방법: 미정

샘플과 실제 구현이 같은 계약을 사용하도록 한다. 소비자는 샘플로 먼저 연결할 수 있다.
