## 제품을 한 문장으로

- 대상 사용자: 인천대 사이버캠퍼스(lms.inu.ac.kr)에서 녹화·비대면 강의를 듣는 학생
- 그 사용자가 지금 겪는 구체적 문제: (제안) 녹화 강의를 혼자 들으면 미루게 되고 집중이 안 된다. 어떤 영상이 밀렸고 과제 마감이 언제인지 LMS 여러 화면을 뒤져야 안다.
- 핵심 동작과 결과: 학번으로 로그인하면 3D 강의실에 들어가 걸어 다닐 수 있고, 내 강의와 이번 주 영상 목록이 뜬다. 영상을 고르면 LMS 창에서 재생되어 진도율이 그대로 기록되고, 그 화면이 강의실 칠판에 내 화면에서만 비친다. 같은 방의 다른 학생들도 아바타로 함께 있지만 각자 칠판에는 자기 강의만 보인다. 앞에 선 AI 교수님에게 모르는 것을 물어볼 수 있다. 비밀번호와 토큰은 브라우저에서 LMS로 직접 보내고 우리 서버에는 보내지 않는다.
- 주제·평가 기준과 연결되는 이유: 혼자 듣던 사이버 강의를 "같이 듣는 강의실"이라는 새 경험으로 바꾸고(창의력: 참신성), 실제 인천대 LMS와 연결해 밀린 강의라는 학교 문제를 다룬다(창의력: 학교 문제 해결성). AI 활용은 여러 에이전트로 병렬 개발한 과정과 프롬프트 로그로 보이고, 제품 안에서는 AI 교수님이 질문 못 하던 학생의 질문에 답한다.
- 1분 데모에서 관객이 확인할 가치: 실제 인천대 계정으로 로그인해 3D 강의실에 들어가면 진짜 내 강의 목록이 뜨고, 고른 영상이 칠판에 재생된다. 심사위원이 QR로 들어와 걸어오면 같은 칠판인데 그쪽 화면에는 내 영상이 보이지 않는다. AI 교수님에게 강의 내용을 물어보면 답한다.

후보는 주제 적합성, 문제의 명확성, 시간 내 구현, 시연 가능성으로 비교하고, 가장 작은 핵심 흐름으로 가치를 보이는 것을 고른다.

## 기능 목록

개수는 정하지 않는다. 우선순위 순으로 나열하고 시간 안에 끝낼 수 있는 만큼만 한다. 기능마다 정상 동작·빈 결과·오류 상태의 완료 조건을 적는다.

단계 순서는 팀 확정(2026-11-06): 1차 → AI 교수님 → 강의실 여러 개 → 캐릭터 변경 → 학교 게시판 → 학교 건물. 순서는 우선순위이며, 골격(T1)이 끝나면 앞 단계가 끝나지 않아도 뒤 단계를 병렬로 시작한다. 14:08에 새 기능을 멈출 때 뒤 순위부터 자른다. 각 기능의 세부 완료 조건은 (제안)이다.

| 환경 변수 이름 (값은 `.env.example`에 쓰지 않는다) | `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`. LLM 키 이름은 제공사가 정해지면 추가 |
| 프롬프트 로그 | 평가 항목이므로 처음부터 남긴다. 각 에이전트의 대화 기록 파일(Claude Code의 프로젝트별 `*.jsonl`, Codex의 `~/.codex/sessions`)을 마지막에 모아 비밀값을 가린 뒤 `docs/prompt-log/`에 넣고, 대표 프롬프트를 골라 이유를 적은 `docs/prompt-log/README.md`를 만든다. 학번·비밀번호·토큰은 에이전트 대화에 절대 입력하지 않는다 |

(제안) 아래 전체. Moodle 응답 구조는 실제 계정 확인 결과(영상 모듈 이름, 수강 완료 정보 유무)를 받은 뒤 확정한다.

- 생산자 / 소비자 / 계약 파일 경로:
  - LMS: 생산자 `src/lms/client.ts`(실제), `src/lms/sample.ts`(샘플) / 소비자 로그인 화면, 강의 패널, AI 교수님(강의 이름 맥락) / 계약 `src/contract/lms.ts`
  - 같은 방: 생산자·소비자 `src/room/`(Supabase 채널) / 소비자 아바타, 인원 수, 강의실 목록 / 계약 `src/contract/room.ts`
  - 칠판 영상: 생산자 `src/screen/`(화면 공유 `MediaStream`) / 소비자 칠판 컴포넌트 / 네트워크로 보내지 않는다
  - AI 교수님: 생산자 `api/professor.ts` / 소비자 질문 창 / 계약 `src/contract/professor.ts`
  - 학교 공지: 생산자 `api/notices.ts` / 소비자 벽 게시판 / 계약 `src/contract/notices.ts`
- 입력 필드·타입·필수 여부:
  - `LmsClient.login(username: string, password: string): Promise<LmsSession>` (둘 다 필수). `LmsSession = { token: string; userId: number; fullName: string; isSample: boolean }`
  - `LmsClient.getDesk(session: LmsSession): Promise<DeskData>`
  - 강의실 목록: `src/rooms.ts`의 고정 배열 `Room = { id: string; name: string }` (예: `{ id: "room-301", name: "7호관 301호" }`)
  - presence(채널 `campus` 하나, 모든 방 공통): `{ key: string /* 탭마다 임의 값 */; nickname: string; roomId: string; avatar: { preset: string; color: string }; status: "idle" | "watching" | "away" }`. 방별 인원 수는 이 presence를 `roomId`로 세어 구한다
  - 이동 broadcast(채널 `room:{roomId}`, 이벤트 `move`, 초당 최대 10번): `{ key: string; x: number; z: number; rotY: number; at: number }`. 받는 쪽은 보간한다
  - 강의명·영상 제목·화면은 다른 사람에게 보내지 않는다
  - AI 교수님 요청 `POST /api/professor`: `{ question: string /* 필수, 1~500자 */; courseName: string | null; lectureTitle: string | null; history: { role: "student" | "professor"; text: string }[] /* 최근 6개까지 */ }`. 응답: `{ answer: string }`
  - 학교 공지 `GET /api/notices?board=246&row=5`: 응답 `{ board: number; items: { title: string; url: string; publishedAt: string }[]; fetchedAt: string }`. 게시판 번호 후보는 246, 247, 249(각 게시판 이름은 홈페이지에서 확인해 `src/contract/notices.ts`에 적는다). 서버에서 5분 캐시
- 성공·빈 결과의 형태와 예시:
  - `DeskData = { user: { fullName: string }; courses: { id: number; name: string }[]; lectures: LectureItem[]; deadlines: Deadline[]; fetchedAt: string; isSample: boolean; partial: boolean }`
  - `LectureItem = { id: string; courseId: number; title: string; url: string; week: string | null; dueAt: string | null; done: boolean | null /* 완료 정보가 없으면 null */ }`
  - `Deadline = { id: string; courseId: number; title: string; dueAt: string; url: string; kind: "vod" | "assign" | "quiz" | "other" }`
  - 빈 결과: LMS는 `courses`, `lectures`, `deadlines`가 빈 배열이고 `partial: false`. 공지는 `items: []`
- 실패 코드·사용자 메시지·타임아웃:
  - LMS(`LmsError.code`): `invalid_login` → "학번이나 비밀번호가 맞지 않아요" / `network`, `timeout`(10초) → "LMS에 연결하지 못했어요. 샘플로 둘러볼 수 있어요" / `denied`(웹 서비스 함수 권한 없음) → "LMS가 이 정보를 열어 주지 않았어요" / `expired` → 로그인 화면으로 돌아가며 "다시 로그인해 주세요"
  - AI 교수님: HTTP 400(빈 질문·길이 초과) → 보내기 전에 막는다 / 502·타임아웃 15초 → "교수님이 잠시 자리를 비웠어요. 다시 물어봐 주세요"
  - 학교 공지: 502·타임아웃 8초 → "학교 홈페이지에 연결하지 못했어요"
  - 실시간 연결 끊김 → "혼자 모드" 표시, 자동 재연결
- 샘플 데이터 경로 / 실제 구현으로 바꾸는 방법: LMS는 `src/lms/sample.ts`(데이터 `src/samples/desk.json`, 빈 상태용 `src/samples/desk-empty.json`). 화면은 `LmsClient` 인터페이스만 쓰고, "샘플로 둘러보기"면 샘플 구현, 로그인하면 실제 구현을 넣는다. `isSample`이 참이면 "샘플 데이터"를 표시한다. AI 교수님과 공지는 서버 함수가 생기기 전까지 `src/samples/professor.json`, `src/samples/notices.json`을 같은 형태로 돌려주는 클라이언트 함수(`src/api/professor.ts`, `src/api/notices.ts`)로 먼저 연결하고, 화면에 "샘플"을 표시한다.
- 공유 파일(골격 T1에서 먼저 만들고, 이후 수정하는 작업끼리는 의존으로 순서를 정한다): `package.json`, `src/contract/*`, `src/App.tsx`(화면 전환), `src/scene/Classroom.tsx`(장면 루트, 자식 컴포넌트는 각자 파일), `src/rooms.ts`, 전역 스타일 `src/styles.css`, `vercel.json`.
