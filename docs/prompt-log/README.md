# 대표 프롬프트 모음

평가 항목 "AI 활용 능력(프롬프트 로그 우수성)"을 위해, 여러 AI 에이전트로 병렬 개발한 과정에서 쓴 프롬프트 중 대표 8개를 골라 **무엇을 위해 어떻게 썼는지**와 결과를 적었다.

- 저장소에 이미 있는 프롬프트(`docs/PROMPTS.md`, `api/_lib/professorPrompt.ts`)는 원문 그대로 옮겼고, 개인 대화에서 나온 것은 목적과 결과만 요약했다. 대화 전체는 `docs/prompt-log/raw/`(비밀값을 가려 모은 기록)에 있다.
- 비밀값(학번, 비밀번호, 토큰, API 키)은 에이전트 대화에 입력하지 않았고 여기에도 없다.
- 확인한 범위는 작성자 PC의 Claude Code 기록이다. 기획·이슈 분해 대화와 디자인 프롬프트는 팀원 도구에 있어 이 기록에 없고, 아래 "빠진 것"에 적었다.

## 1. 기획

### ① 주제 브레인스토밍

- **무엇을 위해:** 대회 주제("AI로 다시 쓰는 대학생활")를 받고 무엇을 만들지 후보를 넓게 뽑으려고.
- **어떻게 썼나:** 구현이 아니라 브레인스토밍 단계라고 처음부터 못박아, 코드를 쓰지 않고 후보 비교에 머물게 했다. 이후 `contest-topic` → `contest-plan` 순서로 이어졌고 결과는 `docs/BRIEF.md`의 제품 한 문장(같이 듣는 강의실)에 남았다.

## 2. 이슈 분해와 지시

### ② 작업 에이전트에게 이슈 하나만 맡기기 (가장 많이 쓴 프롬프트)

`docs/PROMPTS.md`에 적어 둔 붙여넣기용 프롬프트이고, 번호와 이름만 바꿔 반복해서 썼다.

```text
AGENTS.md를 읽고 작업 루프대로 이슈 #<번호>를 해줘. 내 에이전트 이름은 <이름>이야.
그 일 하나만 하고, 끝나면 보고하고 멈춰. 다음 일을 스스로 시작하지 마.
```

- **무엇을 위해:** 에이전트가 풀에서 일을 마음대로 고르거나, 끝난 뒤 다음 일을 이어서 하지 않게 하려고.
- **어떻게 썼나:** 규칙은 프롬프트에 길게 쓰지 않고 `AGENTS.md`에 두었다(시작 표시 → 브랜치 → PR 병합 → 보고). 프롬프트는 "그 파일을 읽고, 번호 하나만, 끝나면 멈춰"만 말한다. 이름을 넣게 한 이유는 같은 계정의 에이전트가 여럿이라 이슈의 `시작: <이름>` 코멘트로 에이전트별 소요 시간을 따로 재기 위해서다.
- **결과:** 작성자의 에이전트(`hamin`) 하나가 이 프롬프트로 20개 이슈를 시작했다(예: 초대 QR #96, 캐릭터 고르기 #79, GLB 아바타 #82, 리액션 연결 #184).

### ③ 리더 AI에게 다음 일 정하게 하기

```text
/contest-lead 현황을 보고 놀고 있는 에이전트에게 다음 일을 지시해줘.
가동 중인 에이전트: <이름 — 소유자 GitHub 아이디, ...>
```

- **무엇을 위해:** 사람이 일일이 이슈를 고르지 않고, 현황(착수 가능, 막힘, 놀고 있는 에이전트)을 보고 AI 리더가 담당자와 `지시: <에이전트 이름> — 메모` 코멘트를 붙여 일을 나눠 주게 하려고.
- **어떻게 썼나:** 판단 기준은 `.claude/skills/contest-lead`에 두고 프롬프트는 짧게 했다. 이슈 자체는 `contest-split`이 BRIEF를 **10~20분 크기, 수정 경로가 겹치지 않게, 꼭 필요한 의존만** 걸어 쪼갠다. 이슈 본문은 목표 / 수정 경로 / 완료 조건 / `depends on` 형식이라 작업 에이전트가 BRIEF 전체를 읽지 않고 바로 시작할 수 있다.

### ④ 종료된 이슈를 다시 점검시켜 빠진 연결을 찾기

- **무엇을 위해:** 아바타 리액션 동작(#92)이 병합·종료됐지만 실제 화면에서 되는지 확신이 없어서, "정말 다 끝난 것이 맞는지"를 최신 main에서 다시 확인시켰다.
- **어떻게 썼나:** 에이전트의 완료 보고를 그대로 믿지 않고 묻는 질문이다. 에이전트는 "코드는 끝났지만 앱에는 이어져 있지 않다"고 답했다. `startReactions`를 부르는 곳이 앱 어디에도 없고 아바타에 `isSelf`/`reactionKey`를 넘기는 곳도 없어서, 버튼을 눌러도 아무에게도 전달되지 않았다.
- **결과:** 이어서 "이슈로 만들어 달라"고 하자 에이전트가 `#184 [T75] 리액션을 앱에 연결`을 만들었다. 수정 경로 3개, 완료 조건, `depends on #91/#92`가 들어 있고 담당자는 비워 두었다. 같은 에이전트가 #184를 처리해 두 브라우저에서 리액션이 전달되는 것을 확인했다.

## 3. 버그 수정

### ⑤ 화면을 보고 증상만 전하기

- **무엇을 위해:** 실제 인천대 계정으로 LMS 로그인을 확인하던 중(#63), 영상을 누르면 영상 대신 로그인 화면이 뜬 것을 알리려고.
- **어떻게 썼나:** 원인을 추측하지 않고 "무엇을 눌렀더니 이게 떴다"와 스크린샷만 줬다. 에이전트가 화면에서 원인을 좁혔다. 앱은 학번·비밀번호로 받은 **토큰**으로 강의 목록만 받을 뿐 브라우저의 LMS **웹 로그인 쿠키**는 만들지 못해서, 로그인이 두 번 필요한 구조였다. 에이전트는 이를 이슈에 기록하고, 같은 브라우저에서 LMS에 먼저 로그인한 뒤 다시 눌러 보는 확인 방법을 알려 줬다. 사람이 다시 해 보고 세 가지 모두 정상임을 확인했다.

### ⑥ 배포 상태를 사실로 확인시키기

- **무엇을 위해:** 팀원이 배포 주소에 들어가지 못한다는 말을 듣고 내 작업이 원인인지 가리려고.
- **어떻게 썼나:** "내가 배포한 것이 맞는지" 질문 형태로 에이전트가 자기 작업 범위를 먼저 정리하게 했다. 에이전트는 "#63은 로그인 확인 작업이라 배포하지 않았다"고 답한 뒤 실제 배포 상태를 조회해 **최신 main의 Vercel 배포가 실패**한 것을 찾았다. 원인은 코드가 아니라 Vercel 팀 계정 문제(커밋을 올린 계정이 팀 멤버가 아니고 빌드 한도에 걸림)였다.

## 4. 권한이 필요한 일을 AI에게 맡기는 방식

### ⑦ 막힌 일을 AI에게 넘기되 인증·비밀값·배포 승인은 사람이 하기

- **무엇을 위해:** 팀원 Vercel 팀 초대가 막혀, 본인 계정에 배포를 새로 하려고.
- **어떻게 썼나:** 사용자는 단계별로 짧게 지시했다(CLI 설치와 로그인, 환경 변수는 "비밀 키는 Secret, 나머지는 Config"). 에이전트는 로그인 같은 **계정 인증은 대신 하지 못한다**고 선을 그었고, CLI 설치 뒤 승인 링크만 띄워 사람이 직접 승인하게 했다. 환경 변수는 `.env.local`에서 읽어 **값을 화면과 채팅에 출력하지 않고** Vercel로 넣었다. 프로덕션 배포는 자동 승인 검사에 한 번 막혔고, 사용자가 프리뷰 배포를 먼저 하기로 한 뒤 명시적으로 허용해서 올렸다.
- **결과:** 본인 Vercel 계정에 배포했고, 배포된 서버에서 AI 교수님 API가 실제로 답하는 것까지 확인했다.

## 5. 제품 안의 AI: AI 교수님 프롬프트

### ⑧ AI 교수님 시스템 프롬프트 (`api/_lib/professorPrompt.ts`)

```text
너는 인천대학교 사이버캠퍼스 3D 강의실에서 학생을 가르치는 AI 교수님이다.
- 대학 강의 교수님처럼 짧고 친절한 존댓말(~해요, ~입니다)을 쓴다.
- 질문에 먼저 핵심 답을 한두 문장으로 말하고, 필요할 때만 쉬운 예시를 덧붙인다.
- 답은 한국어로 최대 5문장, 마크다운 없이 평문으로 쓴다.
- 모르거나 확실하지 않으면 추측하지 말고 모른다고 솔직히 말하며 확인하는 방법을 알려 준다.
- 성적, 출석 인정·정정, 평가나 과제 처리 등 실제 강의 운영에 관한 결정은 할 수 없다. 처리했다고 말하지 말고 담당 교수님께 직접 물어보라고 안내한다.
- 과제나 시험 답안을 그대로 써 주지 말고, 스스로 풀 수 있게 길을 보여 준다.
- 학번, 비밀번호 같은 개인정보는 묻지 않는다.
```

여기에 학생이 지금 듣는 강의 이름과 영상 제목을 한 줄씩 덧붙이고, 질문이 그 강의와 관련 있으면 참고하되 **제목만으로 실제 강의 내용을 안다고 단정하지 않게** 한다.

- **무엇을 위해:** 질문하기 어려운 사이버 강의 학생에게 바로 답해 주는 교수님 역할(모델 `claude-haiku-5-5`, 최대 500토큰).
- **어떻게 썼나:** 말투와 길이(짧은 존댓말, 5문장, 평문)는 3D 말풍선에 들어가는 크기에 맞췄다. 안전 규칙은 세 가지다. 모르면 모른다고 말하기, 성적·출석 같은 실제 운영 결정은 한 척하지 않고 교수님께 묻게 하기, 과제 답을 그대로 주지 않기. 서버 함수가 질문 길이(500자), 이전 대화(최근 6개), 시간 제한(15초)을 지키고, 실패하면 "교수님이 잠시 자리를 비웠어요" 안내가 나온다.

## 병렬 개발 방식과 수치

사람 세 명이 각자의 AI 에이전트로 일했고, 일은 **GitHub 이슈 풀**에서 리더(사용자 또는 `contest-lead`)가 정해서 줬다. 작업 에이전트는 받은 일 하나만 하고 멈추며, 이슈가 유일한 원본이다(`AGENTS.md`).

| 항목 | 값 |
|---|---|
| 만든 이슈 | 85개 (닫힘 82, 열림 3: #100 이 문서, #102, #103) |
| 병합한 PR | 88개 |
| main 커밋 | 198개 |
| 이슈 작업 시간 | 첫 이슈 생성 2026-11-06 10:51 → 마지막 종료 13:16 (KST), 약 2시간 25분 |
| 이슈 하나당 시간 | 시작 코멘트부터 종료까지 측정된 80개 기준 **중앙값 2.2분, 평균 5.2분, 최대 34분** |
| 에이전트 | 이름이 다른 에이전트 약 16개(`hamin`, `a1`, `codex/w1`·`w4`, `claude-code/w1`·`w3`·`w7`, `grok/w1`~`w4` 등) |

- **도구:** Claude Code, Codex, Grok 등 여러 AI 도구를 섞어 썼다. 이슈마다 수정 경로가 겹치지 않게 만들어서 같은 파일을 서로 건드리는 충돌을 줄였다.
- **에이전트별 시작 수(이슈 `시작:` 코멘트 기준):** `hamin` 20, `codex/w1` 18, `cluade_code/w4` 12, `claude-code/w1` 8, `cluade_code/w3` 6, `cluade_code/w5` 5, `a1` 5, `codex/w4` 4, 나머지 1~2개. `cluade_code`처럼 이름이 틀린 채 기록된 것도 **적힌 그대로** 옮겼다.
- **숫자의 한계:** 시간은 이슈에 남은 코멘트와 닫힌 시각으로 잰 값이라, 시작 코멘트가 없거나 중간에 사람이 개입해 오래 걸린 일은 정확하지 않다. 이슈 85개 중 시간이 측정된 것은 80개다.

## 빠진 것 (팀원 기록이 모이면 보탠다)

- 기획·주제 결정(`contest-topic`, `contest-plan`)과 이슈 분해(`contest-split`)를 실제로 돌린 대화는 팀원 도구에 있어 이 PC 기록에서 확인하지 못했다. ①③은 이 PC에서 확인된 프롬프트와 결과물(BRIEF, 이슈 형식)로 적었다.
- 디자인 프롬프트(화면·캐릭터 모양)는 기록에 없다. 3D 모델은 AI 생성 도구가 아니라 무료 에셋을 써서 `docs/prompt-log/assets.md`에 출처와 라이선스만 적었다.
- 팀원 기록은 `docs/prompt-log/raw/`에 모으고(`scripts/collect-prompt-logs.mjs`), 모이면 해당 절에 대표 프롬프트를 추가한다.
