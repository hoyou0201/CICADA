# 3인 협업과 AI 사용

## 역할 초안

실명과 경험은 아직 미확인이다. 주제 공개 후 기능·경로를 확정하고 [기획서](BRIEF.md)에 기록한다.

| 사람 | 기본 책임 | 개발 산출물 | 사용하는 도구 |
| --- | --- | --- | --- |
| A · 본인 | 범위 조율·통합·공통 설정·배포 | 최소 앱 골격과 연결, 배포 가능한 통합본 | Orca 안의 Codex·Claude·Cursor·Antigravity |
| B · 팀원 1 | 핵심 사용자 흐름 1 | 자기 기능의 화면·동작·필요한 검증 | Antigravity |
| C · 팀원 2 | 핵심 사용자 흐름 2 | 자기 기능의 화면·동작·필요한 검증 | Antigravity |

B와 C는 각자 완료 가능한 기능을 맡는다. 예: B는 입력→검증→제출, C는 결과→상세→저장.
이는 분담 예시이며 구현할 제품의 확정 사항이 아니다.
A가 모든 API·검수·발표를 떠안지 않게 기능별 데이터 처리도 B/C가 담당한다.
발표자는 가장 잘 설명하는 사람, 시연자는 실제 동작을 가장 잘 아는 사람으로 리허설에서 정한다.

## 본인의 여러 AI 도구 사용

도구마다 특정 능력이 더 좋다고 전제하지 않는다. 역할을 고정하면 중복 구현을 줄일 수 있다.

- 구현 도구 1개: 현재 작업의 유일한 수정 담당.
- 검토 도구 1개: 변경 diff와 완료 조건을 읽고 문제·재현 방법을 보고. 검토 중 파일 수정은 하지 않음.
- 다른 도구: 막힌 문제 조사 또는 별도 경로 작업. 모델 한도에 도달하면 인수인계 후 전환.
- 동시에 수정하려면 독립 checkout + 독립 브랜치 + 서로 겹치지 않는 경로가 필요하다.
- Orca에서 새 작업 공간을 쓸 때 실제 경로·브랜치를 먼저 확인한다. 팀원의 Antigravity 사용에 Orca는 필요 없다.

## Git 협업

각자 별도 clone을 쓰고, 작업마다 `feat/a-기능`, `feat/b-기능`, `feat/c-기능`처럼 사람과 기능을 표시한다.
AI 도구명으로 작업자를 구분하지 않는다. 한 사람의 여러 도구가 동일 작업의 다른 버전을 만들 수 있기 때문이다.

아래는 **공유 준비 브랜치가 main에 반영된 뒤**의 예시다. 미커밋 변경이 있으면 먼저 보존한다.

```sh
git status --short --branch
git fetch origin
git switch -c feat/b-input origin/main
```

작업이 끝나면 변경 파일을 확인하고 **담당 파일만** staging한다. 전체 폴더를 무조건 추가하지 않는다.

```sh
git diff
git add docs/BRIEF.md
git diff --cached
git commit -m "docs: agree MVP scope"
git push -u origin HEAD
```

위 `git add`는 기획서 변경 예시다. 실제 작업에서는 해당 파일 경로로 바꾼다.
GitHub에서 main 대상 PR을 열고 [PR 양식](../.github/PULL_REQUEST_TEMPLATE.md)의 검증을 채운다.
통합 담당은 작은 PR부터 순서대로 반영한다. 배포 기준은 main으로 통일한다.

작업 중 main이 바뀌면 깨끗한 작업 디렉터리에서 다음을 실행한다.

```sh
git fetch origin
git merge origin/main
```

충돌은 해당 파일 담당자와 해결하고 관련 검사를 다시 실행한다. 잘 모르겠으면 `git merge --abort`로 병합만 취소한다.
공유 브랜치의 강제 push, 다른 사람의 작업 제거, `reset --hard`로 충돌을 없애는 방식은 쓰지 않는다.

## 통합 간격

- 첫 번째 통합: 전체 시간의 25% 이내에 입력부터 결과까지 아주 얇은 흐름을 연결한다.
- 이후 30~45분마다 짧게 작동 결과·막힘·다음 변경 파일을 공유한다. 더 짧은 대회라면 간격을 줄인다.
- 공통 설정·패키지 추가·lockfile·전역 스타일·라우트는 A가 통합한다. B/C는 변경 요청을 전달한다.
- 구현 결과와 PR 검토가 끝난 것을 구별한다. 브라우저와 배포 검증은 실제 환경에서 따로 기록한다.
